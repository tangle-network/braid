# Beyond harness routing

Updated 2026-10-07. Conditional long-term bets, not predictions of AGI, current capabilities, or five simultaneous projects.

If models become dramatically more capable, the scarce parts may shift toward choosing worthwhile work, obtaining real-world feedback, controlling authority, preserving continuity, and establishing that an outcome is correct. Raw agent count becomes less informative.

Harness routing may become less valuable if native products converge or one system handles most work well. The lasting opportunity is ownership of an agent's working methods and commitments across those changes. Braid should remain useful even when the user stops caring which harness runs underneath it.

## 1. An agent that grows with one person

The user talks to one agent that learns how to help them over time. Its [root AgentProfile](root-agent.md) defines how it discovers objectives, develops working methods, creates other profiles, and learns from outcomes. A large organization of agents is one possible result. A continuing conversation or a small reliable routine may be more useful.

The same mechanism can support a person's business, research, decisions, practical responsibilities, or personal reflection. It needs the appropriate knowledge, tools, and authority for each application; changing a profile alone does not establish competence or professional qualifications. The user can change priorities or providers without losing control of their agent's development.

The hard problem is preserving the user's intent as tasks, models, and priorities change. Stronger planning does not determine which commitments remain wanted.

First proof: sustain one useful relationship or commitment across interruptions, a model change, and a changed priority. Compare benefit and user effort with the existing way the user meets that need. Reject the approach if the user spends more effort correcting its agenda than receiving help.

## 2. A research organization that accumulates discoveries

A person funds a research question. Agents search prior work, pursue competing explanations, run computations, request external experiments, reproduce results, and retain failed approaches. The user converses about evidence and decisions while work continues over weeks.

The durable result includes claims, provenance, experiments, artifacts, unresolved objections, and reusable methods. A hypothesis, simulation, formal proof, and physical measurement remain different kinds of evidence. Human researchers and external laboratories can be participants through bounded tools and workflows.

The hard problems are valuable question selection, independent verification, data access, and experiment latency. More generated papers are not sufficient progress. Existing [research systems](evidence.md) make the relevant baseline demanding.

First proof: produce one independently reproducible result on a bounded problem. Compare with a researcher using a strong native harness under comparable resources, elapsed time, and human supervision. Retain every attempted approach and its cost. Reproducibility establishes validity; the comparison must establish added value.

## 3. Products that maintain outcomes continuously

A product accepts a bounded ongoing commitment such as keeping an integration working, maintaining a business forecast, or supporting an irrigation plan as conditions change. It observes change, proposes work, executes within granted authority, checks the result, and escalates consequential choices. Braid is an operator interface to the same underlying work.

This changes the unit of service from a completed chat to an outcome maintained over time. The agent may write temporary code or interfaces when useful, but existing software remains appropriate where it already works.

The hard problem is specifying what should remain true without allowing the system to improve the metric while harming the user's actual goal. Commitments need measurable acceptance, revocation, and explicit boundaries for external effects.

First proof: maintain one service objective through controlled changes and failures. Count incidents, unnecessary interventions, total cost, and time spent by the owner. Expand only if the complete service beats the existing workflow.

## 4. A network that transfers verified working methods

An improvement discovered for one task becomes a reusable profile revision, skill, tool, workflow, or trained specialist with a record of where it helped and where it failed. Another user can reproduce the result before adopting it. Useful methods accumulate across organizations and model generations without requiring everyone to surrender private histories.

The ambitious claim is that work improves future work beyond the original session. Shared methods must outperform starting fresh with an equally capable model; successful copying of configuration is insufficient.

The hard problems are transfer across environments, stale evidence, hidden data leakage, and evaluations that reward appearances. Sharing requires explicit scope, exact dependencies, provenance, and a separation between public methods and private memory.

First proof: a method learned in one setting improves held-out work in another under comparable resources. Include transfer failures and the cost of learning and validation. Keep methods optional when their benefit is local.

## 5. A market for independently verifiable agent work

A pursuing agent can procure a bounded contribution from another operator: a benchmark run, reproducible experiment, formal check, or narrowly specified implementation. Each assignment has a resource ceiling, artifact requirements, and an acceptance process. Tangle could supply execution environments, provenance, and settlement integrations.

This expands a fleet beyond one operator's installed agents. It is worthwhile only when specialized or independently operated workers improve outcomes enough to justify procurement and integration.

The hard problem is verification. Identity, signatures, or execution attestation can establish who ran what; they do not prove that the result is useful or true. Reputation also needs a defined task distribution and resistance to manufactured agreement. Billing and commercial rules stay with their existing owners.

First proof: compare externally supplied work with in-house execution on a task with an independent checker. Include verification, failed bids, disputes, and integration in the total cost. Defer a general marketplace until a narrow exchange demonstrates value.

## Choices to preserve now

- Keep identity and user-owned configuration independent of any one model, subscription, or terminal.
- Keep durable work state outside a conversational context window, with one authority for each assignment.
- Keep result verification independent from the candidate being improved.
- Preserve exact provenance and negative results, without treating private traces as automatically shareable.
- Let learning improve reusable methods and bounded choices; changes to objectives, permissions, or acceptance require their existing authority.
- Reuse Runtime, Eval, and Cloud contracts so Braid and other products can direct the same work.

The first moonshot is the general direction. Research organizations and continuing services are applications of it. Transferable methods could compound the benefit. A work market is a later hypothesis with substantial verification and economic dependencies.

The next investment remains the [bounded comparison](directions.md#first-convincing-comparison): reliable work, understandable control, and one demonstrated improvement. That experiment should make progress toward the larger vision even if model gains slow or harness routing becomes unimportant.
